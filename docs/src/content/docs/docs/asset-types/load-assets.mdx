A Load asset replicates data between two connections — from a source
database, storage bucket, or file into the warehouse your pipeline runs
on. It's how raw data usually enters a pipeline: no code, just a source
and a target.

## Create one

On the canvas, add an asset and choose **Load**. The main pane presents
inline source controls; target settings live in the properties panel:

- **Source connection** and **source table or object** — where the data comes
  from. The connection picker is grouped into databases, storage, and files;
  once a connection is chosen, Renart browses available tables or bounded
  S3-compatible/GCS objects while still allowing an explicit path.
- **General → Connection** selects the destination. For a database target,
  the asset name is the target relation, such as `raw.exchange_rates`.
  Storage and file targets use an explicit destination path.
- **General → Materialization** controls how each run writes.

Local files are a first-class source: choose the **local** entry and point
the source at a file path (for example `data/exchange_rates.csv`) to load
a CSV that lives in your repository.

## Write behavior

| Choice | Each run… |
| --- | --- |
| **Table (replace)** | Loads into staging and replaces the target table. This is the atomic, schema-refreshing default where the destination supports it. |
| **Table (truncate)** | Keeps the existing table, empties it, then loads all source rows. Use this when views, grants, or other objects depend on the table. |
| **Append rows** | Adds source rows without removing existing rows. An optional update key can limit the source read. |
| **Merge by key** | Updates or inserts rows using the declared primary-key columns. An optional update key can limit the source read. |

On PostgreSQL, replacing a table is blocked when an existing view depends on
it. Choose **Table (truncate)** for that shape. It preserves the relation and
its dependents, but it is not an atomic swap and keeps the table's existing
schema. If the schema needs to change, update the dependent objects before
using **Table (replace)** again.

## Columns and lineage

The upstream dependency is inferred from the source when you save, so the Load
asset takes its place on the canvas automatically. Use **Sync schema** to read
the source's schema into the asset's column list — after that, downstream SQL
assets get completions and type checking against the loaded table like any
other upstream.
