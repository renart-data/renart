Create a local DuckDB pipeline, preview its output, and schedule it. The retail
demo includes its CSV data, so you do not need a warehouse account.

## Before you start

[Install Renart](/docs/installation/) before starting. The commands below also
require Git.

## 1. Start Renart

```bash
mkdir my-pipelines && cd my-pipelines && git init
renart
```

Since the workspace has no pipelines yet, Renart opens the welcome screen
with three options: **Start from a demo**, **Import existing tables**, and
**Start empty**.

## 2. Create the demo project

Choose **Start from a demo** and pick the retail demo — a small seed-and-SQL
pipeline (bundled customer and order CSVs feeding analytics tables) that runs
entirely offline. Renart scaffolds the project files, creates a local
DuckDB connection, and runs the pipeline once so you land in a workspace
with real data in it.

Wait for **Demo materialized**, then open the workspace. The Explorer contains
the retail pipeline and its assets, and Inspect can read their output.

## 3. Read the canvas

In **Build**, select the retail pipeline and choose **Canvas**. Each node is an
asset; arrows connect inputs to the assets that read them. Select an SQL asset,
then choose **Code** or **Split** to read its query.

## 4. Preview and materialize

Open **Inspect** in the results panel. You should see rows from the demo rather
than an empty result. This previews the query without materializing its target.

Click **Review run** to see the assets that would run, with the environment
and source above them. It starts with the assets that are **Out of date**, which
may be none right after creating the demo; choose **All assets** to see every
asset. Nothing runs until you confirm. Close the dialog when you have checked it.

## 5. Put it on a schedule

Open **Run → Schedules** and click **New schedule**. Select the retail pipeline,
the `default` environment, the cron expression `0 9 * * *`, and your timezone.
Under **Deployment**, keep **Deploy current files**: Renart shows the files it
will deploy, then creates the schedule on that deployment. Check the schedule's
next run time.

Deployment saves a pipeline version; it does not run the pipeline. Scheduled
runs appear under **Run → Runs**, with timing and logs for each asset. Keep
Renart and the machine running for the schedule to fire. You can pause the
schedule from its row after trying it.
