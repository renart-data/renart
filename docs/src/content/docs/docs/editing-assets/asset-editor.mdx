Open any asset from the canvas or the Explorer to edit it. The editor is
pipeline-aware: it knows the asset's upstreams, their columns, and their
types, so problems show up while you type instead of in tomorrow's failed
run.

## Write SQL that knows your pipeline

- **IntelliSense** completes authored assets and positively observed tables
  from the selected warehouse, with known columns and types.
- **Validation** flags unresolved tables and columns inline as you type. A
  confirmed remote table is a warning until an authored source asset represents
  it; the warning offers the same reviewed import as Type check.
- **Format SQL** reformats the query in place.
- Edits **autosave to the file on disk** — the file in your repository is
  always what you see in the editor.

## Preview without side effects

The results panel under the editor follows the selected asset:

- **Inspect** — preview the data the asset produces. Safe: nothing is
  written. If the query is broken you get a quiet "Preview failed" card
  with the engine's error.
- **Materialize** — execute this asset for real and stream the output.
- **Query** — run an ad-hoc query against the same environment.
- **Type check** — column/type problems for the asset, the same checks as
  [`renart type-check`](/docs/reference/cli/) in CI.
- **History** — this asset's part in past runs.

## The workbench

To the right of the editor, the workbench shows the asset's metadata as
editable cards:

- **Identity** — name, type, owner, description, tags, and an optional stable
  asset URL used by cross-pipeline dependencies.
- **Materialization** — write behavior (for example view, or table with
  replace).
- **Dependencies** — upstreams inferred from the SQL, plus a searchable
  free-text picker for manual dependencies. Picking an asset from another
  pipeline uses its URL and links back to the producer; a missing URL is shown
  before you add the dependency.
- **Columns** — scan-friendly editable rows for names, types, descriptions,
  ownership, and checks. **Sync schema** compares the asset definition with
  optional live-response or current-table evidence. Safe additions apply
  directly; type or deletion conflicts open a source-by-source resolver, and
  you can always add a declared column manually.

Like everything in Renart, workbench edits land as plain file changes in
your repository, so a form edit and a code edit look the same in review —
see [how it works](/docs/how-it-works/).
