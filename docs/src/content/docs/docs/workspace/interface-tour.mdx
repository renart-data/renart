The top bar has three modes: **Build**, **Run**, and **Explore**. Choose a mode,
then use its tool rail on the left. The project switcher, environment picker,
and Git branch stay in the top bar.

## Build

Use **Build** to edit assets and notebooks or browse source data:

- **Project resources** opens the Explorer with pipelines and asset files.
- **Notebooks** opens analysis documents. An open notebook has **Outline**,
  **Data**, **Add**, and **AI** tools in its sidebar.
- **Data Browser** opens configured databases and object storage.
- **Ad-hoc query** opens a query without adding a pipeline asset.
- **Connections**, **Environments**, and **Project settings** are utility
  tools near the bottom of the rail.

For an asset, **Code**, **Split**, and **Canvas** change the central layout.
The results panel below it contains **Inspect**, **Render**, **Materialize**,
**Query**, and **Type check**. The properties panel on the right groups metadata
into **General**, **Lineage**, **Columns**, and **Checks**. Use **Show properties**
or **Hide properties** to make room without changing the asset.

## Run

The **Run** tool rail contains **Run overview**, **Deployments**, **Schedules**,
and **Runs**. Use it to review saved pipeline versions, manage recurring work,
and inspect execution logs. See [Deployments and scheduling](/docs/scheduling/overview/)
and [Runs and history](/docs/workspace/runs-and-history/).

## Explore

- **Workspace Catalog** shows assets and lineage across pipelines.
- **Dashboards** opens the visual dashboard builder.
- **Reports** opens documents that combine text and visualizations.

See [Dashboards and reports](/docs/presentations/overview/) for a guided workflow.

## Follow a diagnostic

When a warning offers **Open columns** or another navigation link, follow it to
the existing editor control. These links carry the target in the URL, so they
also work in a new tab. Unrelated choices, such as the selected results tab or
left sidebar tool, stay as they are unless the destination needs to change them.

On smaller screens, use the mobile tool tabs to reach the same destinations.

## The environment picker

The environment selected in the top bar (for example `default` or
`production`) is the one previews, materializations, and ad-hoc queries run
against. Environments are defined in the project config — see
[Managing connections](/docs/connections-environments/managing-connections/).
