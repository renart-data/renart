Renart is the all-in-one data pipeline IDE. It combines the editor, notebooks,
presentations, scheduler, and freshness monitor in one open-source tool that
runs entirely inside your git repository — your work is plain files, running
on the warehouse you already use.

## What you get

- **A pipeline canvas** that shows assets, dependencies, and freshness at a
  glance instead of making you reconstruct them from files by hand.
- **An editor that knows your pipeline.** IntelliSense suggests columns from
  upstream assets and validation flags unresolved references while you type.
- **Preview, then materialize.** Inspect any asset with no side effects, and
  materialize it explicitly when you're sure.
- **Catalog-aware SQL.** Complete against authored assets and observed remote
  tables, then review an import when an external relation should become part of
  the project.
- **Notebooks** that combine warehouses, files, object storage, and HTTP data
  in local DuckDB, with SQL, Python, text, controls, and checked charts.
- **Dashboards and reports** composed visually from typed datasets and stored
  as version-controlled definitions.
- **Reviewed deployments and schedules.** Pin a pipeline snapshot to each
  environment, run it on a cron, and inspect its timeline and logs.
- **Freshness you can see.** Renart fingerprints every asset and shows what's
  fresh, edited, stale, or never built, while external source assets remain
  explicitly neutral.

Everything Renart does ends up as an ordinary file change in your repository
— diffable, reviewable, revertible.

:::note[Public alpha]
Renart is in public alpha. The core workflow is available, but expect rough
edges and changes before the first stable release. Read [what public alpha
means](/docs/alpha-status/) before relying on Renart for critical workloads.
:::
