The fastest way to try Renart is the DuckDB quickstart. It creates the Bruin chess sample project in your current Git workspace, adds local DuckDB and chess connections, and materializes the sample pipeline from the Renart onboarding flow.

## Start Renart

Open Renart from an empty Git-backed workspace:

```bash
renart web
```

If the workspace has no pipelines or connections yet, Renart opens onboarding automatically.

## Choose The Quickstart

On the welcome screen, click **Create playground** in the quickstart card. Renart creates and runs the sample, then opens the workspace canvas directly.

![Renart onboarding quickstart card with a chess DAG preview](/quickstart-onboarding.png)

## Explore The Pipeline

Use the canvas tour to inspect the sample data flow:

![Renart quickstart workspace canvas with chess assets](/quickstart-workspace.png)

- `dataset.players` is an ingestr asset that loads chess player profiles into DuckDB.
- `quickstart.games` is an ingestr asset that loads chess games into DuckDB.
- `dataset.player_stats` is a SQL asset that joins players to games and aggregates player counts.
- `my_python_asset` is a tiny Python asset included in the Bruin default template.

The pipeline has already been materialized, so the DuckDB database contains the sample tables.

## Next Steps

Use the quickstart as a safe local playground:

- edit the SQL assets and watch Renart save the underlying files
- materialize the pipeline again from the workspace
- create a downstream asset from the canvas
- replace the sample SQL with your own DuckDB queries

If you already have warehouse tables, go back through onboarding and choose **Import an existing warehouse** instead.
